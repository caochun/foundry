# Action、事务与副作用

## Action 定义

Action 是平台唯一的通用业务写入入口。Domain Pack 通过 Schema 声明参数，通过 YAML 或等价格式声明：

- 参数和目标对象；
- 前置条件；
- 对象效果；
- 关系效果；
- 外部副作用；
- 是否可撤销；
- 幂等键和重试策略。

## 执行顺序

```text
参数校验
→ 对象/关系授权
→ 可选的同意检查
→ CEL 前置条件
→ 开启事务
→ 顺序执行对象和关系效果
→ 写入历史、审计和 Outbox
→ 提交事务
→ 发布事件和执行外部副作用
```

事务提交前的任何失败都回滚对象、关系和历史。提交后的副作用失败不能伪装成数据库事务回滚，应通过 Outbox 重试或补偿 Action 处理。

## 约束

- 不允许通过通用 API 直接绕过 Action 修改生产数据。
- Action 必须支持幂等键或乐观并发版本检查。
- Action 失败必须返回机器可读错误码和可定位的字段或对象。
- Action 审计必须记录主体、租户、目标、输入摘要、前后状态、结果、原因和 trace_id。
- Action 不得直接执行任意脚本；效果类型必须由平台注册并受限。

## 批量操作

批量 Action 必须声明原子性：全量成功、逐项成功或分批提交。每个批次和每个对象的结果都要可追溯，不能只返回一个总数。
