# 外部同步与来源模型

## 模式

同步支持两种模式：

- **Materialized**：把外部记录映射并持久化为本地对象，适合需要本地历史和关系分析的数据；
- **Overlay**：外部读取投影，按 TTL 缓存，只读，不产生本地对象历史。

人员、单位、岗位和任职关系若需要参与监督历史查询，默认采用 Materialized 模式。外部系统仍可以保持主数据权威。

## 同步流程

```text
读取源记录
→ 主键映射
→ 字段转换
→ 来源标记
→ 冲突解决
→ 生成 Object/Link Action
→ 事务写入当前、历史、审计和事件
```

同步不能直接修改当前表绕过历史和审计。

## 冲突策略

支持按字段配置：

- `SOURCE_PRIORITY`：指定来源优先级；
- `LAST_WRITE_WINS`：按来源时间；
- `ACTION_PRIORITY`：受控人工 Action 优先于同步覆盖。

冲突结果必须记录接受或拒绝的原因。

## 主数据边界

平台不自动成为人员或组织主数据的权威来源。每个字段和关系必须声明来源系统、同步方向、是否允许本地覆盖和冲突策略。
