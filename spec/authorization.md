# 认证、授权与租户隔离

## 认证

平台不管理业务账号密码。外部身份提供方通过 OIDC/OAuth2 提供主体、租户和角色信息；服务间调用可以使用 mTLS 或受限 API Key。

## 授权

授权由三部分共同决定：

```text
功能权限 + 当前主体/组织上下文 + 对象或关系数据范围
```

OpenFGA 或等价的关系授权服务负责对象级和关系级判断。业务代码不能只按用户名、固定角色名或前端传入的组织 ID 放行。

## 字段保护

敏感字段必须有明确的字段策略。未被策略允许的字段应被隐藏或脱敏，并在响应中说明被隐藏的字段。关系目标对象必须重新执行目标对象自身的授权和字段保护。

## 租户

每个请求必须有不可伪造的 `tenant_id`。所有对象、关系、历史、审计、血缘和事件都必须按租户隔离。缺失或无法验证租户时拒绝请求。

## 审计要求

以下行为必须审计：

- 授权成功和拒绝；
- 对象和关系创建、修改、终止；
- Action 提交、成功和失败；
- 敏感字段查看；
- 数据同步、冲突解决和人工覆盖；
- 历史查询和批量导出。
