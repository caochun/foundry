# ADR-0007：命令回执与业务同事务

状态：Accepted。日期：2026-09-28。

## 决策

1. Storage SPI提供事务内命令回执读写及一致的事务读取入口。JDBC回执持久化在同库，和对象、关系、历史、审计、outbox在同一事务提交；内存回执随Provider状态提交，仅保证进程生命周期内一致性。
2. 有幂等键的Action优先使用Provider的transactionalCommandReceipts能力。键按tenant/actor/action隔离，绑定manifest、类型声明和规范请求摘要。外置进程内IdempotencyStore只作为无此能力Provider的明确兼容路径，不宣称持久。
3. 每次执行及回放均检查主体、租户、Action权限和对象范围；等待数据库写入锁后再次检查，不能利用旧回执绕过权限撤销。
4. 在写入事务内读取回执与当前参数对象。有成功回执直接返回原结果，不重跑前置条件、效果、审计或事件；请求/配置摘要不一致拒绝。没有回执时执行当前前置条件、期望对象版本和效果。
5. 前置条件失败或事务回滚不保存成功回执。提交结果未知时，重试查询相同键，从数据库决定是否重放，不能猜测失败并重复创建对象。
6. JDBC复用数据库租户写锁，跨Provider/进程竞争只能有一个提交者。内存Provider对提交冲突进行有界重试，只重试明确的事务冲突；不重试任意业务或权限拒绝。
7. 回执只存请求摘要和最小执行结果（成功、Action ID、受影响实体引用），不复制请求中的敏感值。回执不可覆盖，生命周期/归档以后单独治理，不自动过期导致旧请求重新执行。

## 验证

必须覆盖不同Provider实例并发、重启后回放、请求冲突、权限撤销、回滚重试，以及真实子进程在提交前/提交后退出的恢复行为。H2文件库证明本地事务恢复，不替代真实国产数据库验证；外部副作用尚未加入此事务保证。
