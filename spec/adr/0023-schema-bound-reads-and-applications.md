# ADR-0023：读取与应用模型绑定

日期：2026-09-28。状态：模型切换下的本体读/应用门禁已实现；数据一致快照和独立运行配置发布继续推进。

## 问题与SPI

ADR-0022已阻止旧模型事务提交，但旧Provider仍可读取，旧ApplicationService也可能在同一Provider重新绑定后继续使用旧字段声明。将字段改为sensitive时，这会让旧应用继续返回原字段。

新增SchemaBinding，包含不透明激活ID和不可变OntologySchema。StorageProvider增加：

- `schemaBinding()`：返回本实例的绑定；尚未初始化模型时为null，不代表查询数据库最新版本。
- `requireSchemaBinding(context, expected)`：核对本实例和权威共享状态。
- `beginTransaction(context, expected)`：只按指定绑定创建事务，不允许偷偷改用新模型。

默认实现明确不支持，第三方Provider接入受控ApplicationService必须实现这些契约，不能用空检查冒充支持。内存与JDBC均已实现；原不带绑定的事务入口继续供可信SPI调用方使用。

## Provider行为

JDBC对象、关系、历史、双时间查询、遍历及待续执行Action读取，在读取前后检查同一绑定。另一实例激活模型，或者本实例在读取中重新绑定，结果都会被丢弃并抛SchemaVersionMismatchException。检查连接与读取连接顺序使用并及时释放，不持有额外长期连接，单连接池可用。

显式绑定事务在同一待使用连接上检查绑定并捕获模型，防止“应用准备参数后，Provider重新绑定，事务悄悄使用新模型”的竞态；不会为了检查再借第二个连接。提交仍受ADR-0022持久门禁保护。

内存以模型专用随机ID表示一次模型生命周期，普通数据更新不改变ID。模型切换后即使回到相同声明，也不复用旧ID；事务使用捕获的模型，并在提交临界区复核模型ID。已有数据revision冲突机制保留。

SPI仍是可信内部接口，不增加字段遮蔽。独立审计/outbox投递检查等非本体辅助接口不因过去事件属于旧模型而停止投递。

## ApplicationService及计算

ApplicationService捕获一个固定模型视图，配置Schema的规范指纹必须与Provider绑定的模型一致。模型已初始化时在构造应用时捕获身份；为了保留声明/契约生成用途，尚未初始化时允许构造，但首次执行必须绑定到匹配的模型，不能采用另一份声明。

同一Provider重新绑定后，旧ApplicationService不会自动升级。即使旧应用一直未使用，或之后又激活同一份声明，已捕获的旧身份仍失效。需要重建应用的模型、动作注册、字段策略和计算器。

当前值、列表、过滤/排序/Connection、聚合、搜索、历史、关系导航和计算字段在完整读操作前后检查绑定，包括授权、字段投影和计算过程。中途切换不能留下已算出的私有值、计数或空结果。ComputedFieldEvaluator也固定其声明模型，即使直接用于可信计数也不能混用两版声明。

动作在开始时检查应用绑定，并通过显式绑定事务执行。**已在提交门禁内成功提交的动作不会在返回前再被追溯改判失败。** 激活后的新调用/续执行需重建应用；原成功回执的真实性保留。

应用与存储不再接受不同OntologySchema来模拟字段投影。应以完整匹配的模型配置FieldPolicy。额外/旧存储属性仍被声明字段白名单过滤；相关测试改为模拟额外返回值，没有移除未知字段隐藏要求。

## GraphQL与REST

GraphQL运行时渲染模型必须匹配有可信Schema的ApplicationService。一次Query可能包含多个根字段：除了各字段内的检查，默认Instrumentation在整个查询组装结束前再核对绑定；若已切换，清空全部data，避免前一个字段的私有值作为部分结果留下。

返回扩展code=SCHEMA_VERSION_MISMATCH、retryable=false。身份不符为FORBIDDEN；无法核验部署绑定为SCHEMA_BINDING_UNAVAILABLE，均不泄露已经组装的数据。没有请求上下文的纯声明内省仍可离线使用；携带请求上下文的内省也受当前模型门禁约束。宿主自定义Instrumentation须保留或组合此默认检查。

Mutation按每个动作的事务边界处理，结束Instrumentation不会丢弃已经提交成功的结果；执行前的绑定冲突仍返回明确错误。它不是多根Mutation的整体事务实现。

REST沿用409 / SCHEMA_VERSION_MISMATCH / retryable=false处理旧模型读写。读结果在应用层最后一次检查时确定有效；检查之后、网络发送期间发生的切换不追溯撤销已经完成的读取。

## 模型不可变性及数字默认值

模型绑定依赖不可变声明，JSON值不再接受AtomicInteger等可变或自定义Number（包括标准大数类的自定义子类）作为原样持有的数值。标准不可变Java数字继续支持，避免不经过模型切换就修改默认值。

JDBC注册表解码数字默认值时，普通可无损还原的ODL double保持既有形式；不能无损还原的精确小数保留BigDecimal，避免快照重读后指纹漂移。SchemaDiffer按规范数值比较默认值及接口元数据，数字装箱/表示差异不再产生虚假BREAKING变更。该修复针对模型元数据，不宣称所有业务JSON计算提供任意精度。

## 一致性范围与剩余项

这些检查保证操作使用同一模型生命周期，**不是普通业务数据的跨多次读取快照**。同一模型下对象/关系仍可能并发变化，外部FGA也不与关系数据库共用事务；一致读快照、查询下推和批量授权继续实现。

本阶段绑定的是OntologySchema激活ID。动作清单、独立FieldPolicy和FGA资产在应用对象中固定，但如果只改变这些配置、不切换OntologySchema，尚无独立的分布式发布epoch来自动撤销旧应用。完整运行配置发布、应用装配和生产生命周期门禁继续列为待办，不把模型绑定称为全部资产热更新完成。

旧构建或绕过受管API的原始SQL/自定义业务层不会自动得到这些保证，升级仍须按ADR-0022执行。实际目标数据库、性能/资源预算、完整物理漂移和其他上游能力继续验收；运行中的Mirror JAR和业务库未改动。
