# ADR-0006：属性约束与并发写入完整性

状态：Accepted。日期：2026-09-28。

## 决策

1. 对象和关系的创建/更新均校验声明字段，拒绝未知字段、错误类型、缺失必填值；主键由实体ID提供，传入的主键属性必须与该ID一致。更新合并后校验必填，显式null与省略区分。
2. @immutable属性在更新patch中出现即拒绝（与上游一致），即使值相同也不能借此修改；主键同样不可通过patch改动。旧记录原值保留，不自动补造缺失数据。
3. 枚举定义保留到Schema并验证枚举成员；列表元素、JSON/日期等使用通用值校验。字段值复制成不可变结构，防止调用方后续修改绕过校验/历史。
4. @unique按租户、对象/关系类型和字段约束，软删除释放当前唯一占用；空值不占用。同一事务内更新、删除、再创建按真实写入次序维护唯一性。
5. JDBC在首次业务写入取得数据库中的租户写入锁，同一租户同一库的多个Provider事务串行验证约束和关系基数；内存Provider保留快照提交冲突保护。正确性优先于吞吐，后续可按明确锁序细分作用域；不以单进程Java锁冒充跨实例保证。
6. 现有测试与Mirror定义可能依赖原来未校验的缺字段/额外字段。修正真实定义和写入方，不能通过默认宽松开关使测试通过；旧数据读取保留，更新必须满足新约束，迁移由有来源的治理流程完成。

本阶段不宣称完整CEL字段/类型约束、默认值和计算属性已经覆盖，后续继续对齐上游；未完成语义仍列入计划。真实国产库锁语法与性能须实际验证。

## 兼容说明

- 时间属性接受ISO字符串及匹配的Java时间值（如Instant/LocalDate），统一持久化/返回为ISO字符串，避免内存和JDBC返回类型不同。调用方不再假设DateTime属性一定是Instant实例。
- 唯一值校验读取当前有效记录，不自动回填旧数据。发现其他记录的旧重复值时拒绝受影响写入；允许显式把待修复记录改成一个合法未占用的新值。
- 数据库租户锁在现有业务事务内持有，锁行初始化在获取业务连接前完成，不占用嵌套连接。只验证了H2数据库语义，真实国产库及同库不同Schema版本漂移仍需后续注册表/迁移门禁验证。
- 内存实体键使用长度编码，避免租户和实体ID中的分隔符导致跨租户键碰撞。Schema基本类型及字段名称也在Provider应用时检查。
