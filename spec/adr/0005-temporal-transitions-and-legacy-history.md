# ADR-0005：时间转换、终止事实与旧历史边界

状态：Accepted。日期：2026-09-27。

## 决策

1. 普通创建/更新/删除默认从本次服务端记录时间生效，不回溯覆盖原生效区间。所有新历史为完整状态断言，validFrom为本次生效时点、validTo为空。
2. 删除追加从删除生效时点起持续有效的DELETED断言。时间单查返回该终止快照；业务列表默认排除，includeDeleted可查看。先选出该时点最新断言再判断是否删除，不先排除删除记录而复活旧版本。
3. Transaction增加对象/关系对称的effectiveAt重载，允许过去至当前的、相对该实体既有生效顺序不倒退的来源补录。recordedAt始终由服务端Clock分配，不能由调用方提供。未来生效及早于既有最近生效时点的写入拒绝；任意区间追溯更正和未来调度另行设计，不声称本阶段已实现。
4. recordedAt是事务内服务端记录时刻，提交后才可见；不宣称它是数据库物理提交时间。相同生效/记录时间使用实体version消歧。当前表仍是最新已知状态，版本单查/历史列表保留原断言。
5. 时间列表必须同时给出validTime和recordedTime；只给一项拒绝，不能默默退化成当前列表。历史图遍历全部边、起点和目标对象都在相同双时间下有效。
6. JDBC历史增加temporal_format标记：旧行1，新行2。只添加结构和默认标记，不改历史业务时间/值。涉及旧格式的时间查询明确拒绝并要求评估迁移；当前读取、按版本查看和原始历史审计仍可用。普通新写入仍允许，显式补录在有旧历史时拒绝。
7. 关系显式补录须验证两端对象在生效时点已经存在；关系基数按完整已知时间区间检查，不能让一条追溯建立的关系与已终止关系的过去有效区间重叠。多进程并发基数仍须单独强化验收。

## 验收与限制

同一组用例在memory/H2运行，涵盖更新前/后、同时间边界、删除不复活、记录时间隔离、迟到事实、列表分页、对象/关系对称、图端点删除及回滚；PG与国产库仍独立验收。JDBC历史列表/遍历先采用一致快照读取和公共投影语义，后续下推查询优化，不把全量历史扫描作为规模性能已达标。

旧行有效时间缺失不能通过猜测回填。业务现有历史审计无需改写；实际运行库升级须备份并运行本版本增量结构初始化，涉及旧行的时间读取需先明确迁移依据。
