# 通用属性校验：升级与兼容边界

本版本对对象和关系的新建/更新执行声明字段、必填、标量/列表/枚举、唯一及不可变校验，默认不提供跳过校验的写入入口。设计依据见ADR-0006。

## 调用契约

- 主键由createObject/createLink的id参数提供；可以省略属性中的主键。若显式提供，须与id一致；更新patch不得再携带主键。
- 更新采用patch语义；必填校验检查合并后的状态，显式null不同于省略。@immutable字段不能出现在更新patch中，即使值相同。
- 未声明字段拒绝，不能通过属性写入伪造系统元数据。对象/关系类型必须独立命名，属性类型需能被当前Provider识别。
- enum定义进入OntologySchema，列表保留元素是否允许null；新增枚举成员与删除成员分别按兼容/破坏性分类。字段类型变更、收紧唯一或不可变约束按破坏性变化处理。
- Date/DateTime/Duration接受相应Java时间值或ISO字符串，存储和读取统一为ISO字符串。Int规范为32位整数；JSON及列表/映射深复制成不可变结构，避免绕过事务改写内存状态/历史。
- 标准错误为PropertyValidationException，提供code和field，不包含字段实际值。通用REST返回400及同样的安全字段定位。

默认值、readonly、计算属性和完整CEL字段/类型约束仍需后续实现；本文件不声称完整ODL语义已经覆盖。

## 唯一与并发

唯一性以租户、类型和字段为作用域，只统计当前非软删除记录；null不占用。时间值先标准化再比较，等价时区表示不能重复占用同一DateTime唯一值。历史记录不因释放唯一值而删除。

JDBC使用of_write_guards租户行，在当前业务事务首次写入时取得FOR UPDATE锁；不同Provider实例共享同一数据库锁。锁行初始化先释放辅助连接再取得业务连接，单连接池也可工作。同租户吞吐受串行约束影响，未来可在严格锁序和一致性测试基础上细分粒度。

唯一索引为事务内缓存，只在写入成功后更新。后续校验拒绝不能释放旧占用。数据库写入/历史写入发生SQLException后事务标记rollback-only，不能提交半份业务状态。内存Provider由快照提交冲突保证原子性，组合键采用长度编码防止跨租户分隔符碰撞。

该保证要求各写入方使用相同Schema与受控SPI；绕过SPI的SQL写入和同库不同版本Schema漂移不在本阶段保证内，仍须持久注册表与迁移门禁。真实国产数据库的锁和DDL行为未验收。

## 旧数据

旧记录仍可读取和审计，不自动补造缺失字段、不删除未知属性、不猜测日期或清除重复值。更新时检查合并后的完整状态，因此可能暴露已有模型漂移。写入要占用一个已有重复的唯一值时会被拒绝；不因无关重复值阻止其他记录逐项修复；允许显式把待修复对象改成一个满足模型且未占用的新值。

升级前在备份副本上核对声明字段、必填值、类型与唯一范围。若旧字段有业务价值，应先通过Schema迁移明确其含义；若要补齐或清理，应记录来源和操作者。不能用统一假值填满必填字段，也不能以默认宽松模式消除错误。

本次配套修正了测试中不完整的合成事实和Mirror已有生产者遗漏的真实字段，没有运行实际业务数据回填。Schema版本变更门禁仍在上游对齐计划中，Provider基础Schema检查不等于完整迁移系统。

唯一索引不把旧的错误类型自动转换成合法值；这些记录在更新时必须通过完整属性校验并显式修正。不存在一个默认“全库已清洗”的标记。
